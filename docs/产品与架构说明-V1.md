# 四象智投产品与架构说明 V1

日期：2026-11-24。状态：方向已确认，作为后续开发的依据。代码仓库：`bntStock`（https://github.com/xp007123/bntStock）。

新版四象智投（本仓库，下文简称“四象智投”）替代旧版四象智投（`backtest-engine`）继续推进，产品名沿用。旧版暂停研发，PatternLab 作为计算核心和页面结构的来源。本文只记录已确认的方向和必要的设计约束；实施细节在各里程碑开始时补充。

## 1. 定位

**一句话：用历史数据，给你的判断算概率。**

- **用户**：私域推广的 C 端投资者。主体是有经验、有自己方法的投资者，同时包括做个股投研、看上涨概率、做场外期权分析的用户。
- **形态**：云端网页服务，用户登录即用，不需要安装或配置模型 Key。
- **价值**：数字来自确定性计算，过程看得见，到期会结算。敢说“不灵”。
- **不是**：荐股工具、实时行情软件、量化编程平台、实盘交易系统。

## 2. 三个场景，一个引擎

三个场景都归结为同一个问题：**这只股票（或这类情形）未来 N 个交易日的收益分布是什么样的？**

| 场景 | 用户在问 | 引擎怎么回答 |
| --- | --- | --- |
| 问方法 | “我的方法灵不灵？” | 方法触发后的 N 日收益分布，与同期随机买入对照，分市场环境统计 |
| 问个股·上涨概率 | “这只票能涨吗？” | 与当前状态相似的历史情形中，N 日收益大于 0 的比例、分位数、最大回撤分布 |
| 问个股·场外期权（100c） | “这个期限和费率值不值？” | 期限内涨幅超过费率（盈亏平衡）的概率、扣除期权费后的期望结果、最差情形、历史波动率参考 |

**收益分布引擎**是计算核心，在 PatternLab 事件统计的基础上扩展。它支持三种取样方式：

1. 这只股票的全部历史；
2. 与当前状态相似的历史时点；
3. 某个规则（形态）被触发之后的时点。

所有概率、期望、分位数都由引擎计算，模型只负责理解问题、解释结果和综合证据。

## 3. 核心循环

```
① 说出想法或问题 → ② 小四澄清并确认 → ③ 引擎计算 + 团队取证 → ④ 结论与今日名单 → ⑤ 冻结、到期结算 → 回到 ①
```

- **第 ② 步必须确认。** 小四把用户的话转成规则或参数后，要用大白话和示意 K 线给用户确认，确认后才计算。小四翻译错了，后面的统计全错，这是最大的产品风险。
- **第 ⑤ 步：每个判断都会被结算。** 方法筛出的名单、个股概率、场外期权的决定都会冻结保存，到期自动计算实际结果，并和当时的判断对照。这一步给用户每天回来的理由，也是最有说服力的验证。

## 4. 差异化原则

1. **对照基准**：每个统计都和同期随机买入（或该股自身无条件分布）对照，跑不赢就直说。
2. **分市场环境**：分牛市、熊市、震荡市统计，揭示只在特定环境下有效的方法。
3. **防过拟合**：提示样本量不足，用另一段时间的数据检验，提醒反复调参（例如“已调整 8 次”）。
4. **点时冻结**：每个结论只使用当时能拿到的数据；研究记录写明数据版本和证据截止时间。
5. **事实与观点分开**：数字来自工具，带来源；模型给出的是解释和观点，界面上明确区分。
6. **如实说明能力边界**：只有日线数据，不能验证盘中走势；不能把日线条件冒充盘中过程。

## 5. 第一版范围

**做：**
- 日线行情（含指数）、个股看盘、形态测试、研究记录；
- 小四对话：问个股（上涨概率、场外 100c）和问方法；
- Agent 团队，过程可见；
- 判断的冻结与到期结算；
- iFinD 每日数据同步；
- 管理端最小功能。

**不做：**
- 分时、分钟、逐笔数据（以后再考虑）；
- 实盘交易、QMT、账户事实；
- 雪球、敲入敲出等路径依赖的场外结构（第一版只做 100c 平值看涨）；
- 可视化 Agent 编排、可发布的研究组版本体系；
- 执行回测（订单、成交、净值），以后视需求再做简化版；
- 因子研究、LightGBM 模型管线、策略共创等旧版四象智投的研究型功能。

新功能进入范围前，先回答一个问题：**它服务核心循环的哪一步？** 答不上来就不做。

## 6. 产品结构

### 6.1 C 端页面

页面结构沿用 PatternLab，加入小四。

| 位置 | 内容 | 来源 |
| --- | --- | --- |
| 问小四（首页） | 小四形象、对话框、建议问题（问个股、问期权、问方法）、最近研究 | 旧版四象智投首页 |
| 个股看盘 | 证据展示页：K 线、指标、入选原因标注、历史相似案例 | PatternLab |
| 形态测试 | 内置模板创建、研究报告、条件对比、增减条件、最新符合 | PatternLab |
| 研究记录 | 对话、形态研究、期权分析统一列表；结算结果 | 两边合并 |
| 全 A 行情 | 行情和指数概览，次要入口 | PatternLab |
| 小四抽屉 | 每页都可唤出，自动带上当前股票或当前研究 | 旧版四象智投 |

PatternLab 原来的“通过自己的 AI 创建”（描述形态、发截图、指定一段 K 线），改为在小四对话里完成；“从内置模板创建”保留。

**视觉规范（2026-11-24 确定）**
- 沿用旧版四象智投首页（`ResearchHome.css`）的暖色设计：纸色背景 `#fafaf8`，侧栏 `#f0f1ed`，线条 `#e4e6df`，正文 `#272b28`，次要文字 `#7b8179`，主色 `#e65336`，浅主色 `#fbede7`，圆角 16px。
- 涨跌沿用 A 股红涨绿跌：涨 `#d23b33`，跌 `#1e8a4c`，中性 `#948e83`（已通过色盲区分与对比度校验）。主色与涨色同属红色系，主色只用于按钮、选中态等交互元素，数据上的红色一律表示涨或正向。K 线阳线空心、阴线实心，不只靠颜色区分。
- 小四形象直接复用旧版组件（`HomeResearchPet`、`ResearchPet` 与 `research-pet/bloub`），保留 bloub 的 MIT 许可证文件与出处说明。bloub 原作者说明其头像设计复刻 x.ai 的视觉，MIT 只覆盖代码；是否另做原创形象由产品负责人决定，当前决定为直接复用。
- 样板：`prototypes/visual-sample/`（示意数据）。

### 6.2 小四与 Agent 团队

| 角色 | 负责 | 工具来源 |
| --- | --- | --- |
| 小四 | 理解问题、澄清确认、派发、综合、呈现 | — |
| 走势与概率 | 收益分布、波动率、相似历史情形、规则统计 | 自有引擎 |
| 基本面与估值 | 财务、估值所处的历史分位 | fundamentals-mcp |
| 事件与风险 | 期限内的财报日、解禁、新闻事件 | lockup-mcp、news-mcp |
| 市场环境 | 大盘、板块状态 | market-data-mcp、自有引擎 |

约束：
- 协作流程固定为“小四派发 → 专业角色取证 → 小四综合”，写在代码里，不做可视化编排。
- 团队里每一步都对应一次真实的工具调用，用户可以展开查看证据；不安排角色之间为展示而对话。
- 按问题类型决定派哪些角色。问方法通常只需要走势与概率、市场环境；场外期权分析需要全部角色。
- 报告要有阅读主线，不能按资料罗列；图表绑定工具返回的数据，不让模型自由生成图表数据；推理强度不超过证据。

### 6.3 管理端

管理端只管“接入什么、给谁用、用多少”，不管“业务流程怎么走”。

| 功能 | 第一版做法 |
| --- | --- |
| 数据同步状态 | 界面：每日同步结果、当前数据版本、校验失败明细、手动重跑 |
| 用户与配额 | 界面：私域用户名单、对话与模型调用配额、成本统计 |
| 工具与 MCP 登记 | 配置文件：地址、启用状态、允许哪些角色调用、是否支持按历史时点取数 |
| Agent 角色配置 | 配置文件：提示词、可用工具、模型；修改生成版本号，研究记录引用该版本 |

配置需要频繁修改、或者有其他人要来修改时，再给它们做界面。

## 7. 系统架构

```
┌─ C 端网页 ───────────────┐   ┌─ 管理端 ──────────────────┐
│ 问小四 · 看盘 · 形态 · 记录 │   │ 数据同步 · 用户与配额      │
└────────────┬────────────┘   └─────────────┬─────────────┘
             ▼                              ▼
┌─ 核心服务 ─────────────────────────────────────────────────┐
│ 对话与 Agent 运行时 ── 按工具登记表调用工具                  │
│ 收益分布引擎：日线快照、指标、规则、事件统计、相似情形       │
│ 研究记录与结算：冻结判断、到期结算                           │
│ 数据同步：iFinD → 暂存 → 校验 → 发布新版本                   │
└────────────┬───────────────────────────────────────────────┘
             ▼ MCP 协议
   自有工具（引擎能力）  +  外部 MCP（agents-mcp-java）
```

### 7.1 技术选型

| 部分 | 选择 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite；react-router、TanStack Query、ECharts（按需引入） | 构建为静态文件；小四组件源码复制自旧版（`frontend/src/components/xiaosi`） |
| 后端 | Python + FastAPI，包名 `sixiang` | 复用 PatternLab 的计算代码和 pandas/numpy 生态 |
| 后台任务 | Redis 队列 | 运行 Agent 团队、全市场统计、数据同步、到期结算 |
| 业务数据 | PostgreSQL（待定，可改用服务器已有的 MySQL） | 用户、对话、研究记录、判断与结算 |
| 行情数据 | Parquet + DuckDB | 按版本存放快照，替代 PatternLab 的逐股 CSV |
| 实时推送 | SSE | 对话流式输出、团队进度 |
| 大模型 | 支持工具调用的模型 API | 具体模型由 Agent 角色配置决定 |

### 7.2 工具层

- 自有引擎能力也包装成 MCP 工具，与外部 MCP 一视同仁。新增能力通过登记接入，不改核心代码。
- 每个工具在登记时标注**是否支持按历史时点取数**。用户问的是历史某天，而工具只能给实时数据时，运行时拦下这次调用，避免引入未来信息。
- 外部 MCP 来自 `agents-mcp-java`（用户持有该仓库），第一版接入 market-data、fundamentals、lockup、news；其余按需在登记中启用。

## 8. 数据

### 8.1 来源与同步

1. **基线**：导入 PatternLab 随包数据（日线截至 2026-11-18、财务 CSV、14 个指数），生成快照 v0。
2. **补缺口**：用 iFinD 拉取 2026-11-19 至今的数据。
3. **每日同步**：收盘后定时拉取当日数据，先进暂存区，校验通过后发布新版本并原子切换；失败则保留旧版本并告警。
4. **中长期**：用 iFinD 重拉全部历史，作为唯一来源；PatternLab 数据只用于起步和交叉核对。

iFinD 走 HTTP 接口（access_token 鉴权、限制每秒调用次数）。Token 刷新、限流、重试参考旧版四象智投 `backtest-data` 的实现，用 Python 重写。账号额度充足。

### 8.2 规范

- **复权**：只保存不复权的原始价格和复权因子，复权价格由系统计算，避免两个数据源拼接处出现价格跳变。
- **字段统一**：成交额单位、停牌日记录方式、ST 状态、上市与退市日期在导入时统一。
- **校验项**：行数、开高低收的合理性、停牌、新股与退市、复权因子变化。
- **版本追溯**：每份研究记录写明所用数据版本，可复现。

### 8.3 快照实现（M1 骨架）

- 目录：`data/market/versions/<版本>/` 下有 `daily.parquet`、`securities.parquet`、`indices.parquet`、`calendar.parquet`、`manifest.json`；新数据先写 `staging/`，发布时移入并原子替换 `CURRENT`。已有版本不覆盖。
- `daily.parquet` 每只股票一个行组，查询时按代码直接读取对应行组（单只约 10 毫秒）。
- 复权因子：第一天为 1，之后乘以“昨收 ÷ 今日前收盘价”；后复权结果与 PatternLab 一致（已逐日核对）。
- 校验沿用 PatternLab：2007 年起出现异常价格的股票整只拒绝；2007 年前的坏数据只保留之后连续的部分。拒绝原因写入 manifest。
- 基线 `v0-baseline-20261118`：5,907 只股票、1,835 万行日线、14 个指数，截至 2026-11-18 有行情的 5,556 只；拒绝 1 只（sh600625，无有效行情）。

## 9. 部署

- 使用旧版四象智投现有的云服务器（容量不是问题）。
- 先暂停旧版四象智投，再部署四象智投。暂停步骤，每一步执行前都需确认：
  1. 云平台磁盘快照，导出 MySQL，打包各服务配置和当前发布版本；
  2. 停止服务并取消开机自启，不卸载、不删除数据，保证能恢复；
  3. nginx 保留给四象智投使用；frp、legacy-api 先确认用途再决定；
  4. agents-mcp-java 中四象智投需要的 MCP 保持运行或重新部署，其余停止；
  5. QMT 跟踪、事实桥接、Hermes 网关和面板停止。
