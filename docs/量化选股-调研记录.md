## 2. 三个旧仓库各是什么

### 2.1 `bnt-xiao-cheng-xu`：微信小程序

首页有“三角猫·文”“三角猫·邱”“四脚蛇”几个策略卡和一个“候选股”页。

- 三角猫·文：日历选交易日 → 新闻与板块重复度 → 板块里的股票。接口 `/api/sjm/getWenCaiData`、`/api/block-repeat/news-with-statistics`、`/api/block-strategy/pseudo-stocks`。
- 候选股：读 `/api/lt-target/list`，两个池子 `wencai-qiu`（问财多头）和 `wenge-bullish`（文哥多头）。
- 其余页面是实盘下单、持仓、账户映射、AI 分析等。

### 2.2 `bnt_stock_service`：旧后端（Java，已停）

二十多组接口，依赖 Redis、同一个 MySQL 实例上的四个库（`new_stock_data` / `stock` / `trace` / `ai_agent_bnt`）、本机 6598 端口的新闻服务、几家大模型。

和选股有关的只有：

- **三角猫**：每个交易日 09:25:20 调一次同花顺问财（`WenCaiService#buildSJMSearchString`），结果存 `sjm_wencai_stock_data`，再算“正多 / 次多”等因子。历史名单另存 `stock_wencai_sjm`。
- **文哥选股**：它自己不算，只读 `trace.lt_target`。另有一张回测结果表 `stock_wenge_bullish`。

三角猫的选股问句（新四象原样照搬）：

> 非 ST、非科创板、非新股次新股、非北交所；昨日未涨停、昨日换手率小于 5%；总市值低于 500 亿、流通市值大于 10 亿；昨日成交量不大于前日两倍；今日 09:23 未涨停；今日 09:25 未涨停且涨幅最高。

⚠️ `bnt_stock_service/docs/lt_target候选股展示功能设计文档.md` 里明文写着数据库账号和密码。仓库如果推到过远端，建议改密码。

### 2.3 `bnt-qmt-trace-service`：实盘交易引擎（Java，已停，可以启动）

一整套自动交易：09:28:20 下买单，之后按 1 秒到 30 秒盯盘、按规则卖出，带撤单重提、对账、企微通知、多用户隔离。跑三个策略：文哥多头、问财多头（邱）、随机猫（即三角猫，实盘只买其中标了正多 / 次多的）。仓库里 `docs/策略总览.md` 和三份 `策略文档-*.md` 写得很全，先看那几份。

**文哥选股实际是两步：**

1. 每周一次基本面初筛（周末收盘后从 iFinD 拉数，写 `lt_wenge_prescreen`）：归母净利同比 > 40%；每股未分配利润、每股资本公积在申万一级行业内都排前 30%；每股收益不为负；剔 ST 和北交所。
2. 每天 09:26:30 多头判定（写 `lt_target_pool`，池子 `wenge-bullish`）：当天开盘价同时高于 5、10、20 个交易日前的收盘价。按每股未分配利润从高到低排。

**买入前还有十来道过滤**（09:28:20，`WengeEntryStrategy`，按用户逐只判断，结果写在用户维度的表里）：

| 类型 | 哪几道 |
|---|---|
| 和账户有关 | 满仓、冷却池、手动持仓隔离、已持有 |
| 和股票有关 | 5 日低点涨幅不超 17%、昨日冲高回落不超 4.5%、高开不超 4.9%、5 日平均振幅不低于 0.8%、5 日均成交额不低于 3 亿、开盘不涨停、板块指数没有双下拐、站上 20 日线 |

搬到新四象时，和股票有关的那几道要展示出来——用户需要知道哪些票策略实际不会买。

**`codex/myquant-paper-hardening` 分支（本机现在检出的就是它）：** 同一份程序靠环境变量跑成两个实例。

| | 实盘实例 | 模拟实例 |
|---|---|---|
| 数据库 | `trace` | `trace_paper` |
| 下单去向 | QMT | 本机 Python 客户端 → 掘金（MyQuant）模拟账户 |
| 文哥基本面初筛、每日多头精筛 | 跑 | **关掉了** |
| 名单来源 | 自己算 | 09:27 从实盘库单向同步 |
| 策略 | 三个 | 只开了文哥 |

关键点：**模拟实例自己不选股。** 实盘实例停了，模拟实例也拿不到名单。

## 3. 文哥选股以后怎么接（讨论过的方向，尚未动手）

- 选股继续用 Java，不用 Python 重写（现有筛选已经稳定）。
- 起一个“只选股不交易”的实例：这个程序所有定时任务的时间都能用环境变量覆盖，把买入、卖出、盯盘设成永不触发即可，不用改代码。**没验证的一点**：账户 / 持仓 / 订单的轮询好像没有开关，QMT 不在时可能一直刷报错。
- 模拟实例照常跑，它每天会把那十来道过滤真跑一遍，“下单了还是跳过、为什么跳过”都在 `trace_paper` 里——正好是新四象要展示的东西。跳过原因里会混进和模拟账户有关的几种，展示时要分开。
- 新四象只读 `trace_paper`，不写回。
- 需要确认的：模拟实例目前跑在 Windows 本机（掘金终端在 Windows），Linux 部署还没验收；配置里每周拉数的日期列表是人工维护的，停服期间错过的周末要补。

## 4. 这一轮实际做了什么：竞价先锋（三角猫）

代码在 `backend/sixiang/picks/`，页面在 `frontend/src/features/picks/`。

**取名单**

- 新后端直接调问财（iFinD 的 `smart_stock_picking` 接口，用已有的 iFinD 凭证），问句和旧服务一字不差。
- 设环境变量 `SIXIANG_PICKS_AT=09:25:40` 后，每个工作日到点自动取；没取到每分钟重试，最多 8 次；启动时如果已过点还没取，补一次。不设就不自动取。
- 问财能按历史日期查，所以历史名单是直接回填的，没有连旧数据库：
  `python -m sixiang.picks.backfill --start 2026-01-07`
- 存在两张新表：`pick_days`（哪天取过、几只）、`picks`（每只一行）。启动时自动建表。

**算表现**（`picks/stats.py`，全部用新四象自己的日线现算）

- 买入价按当天开盘价：名单 09:25 才出，最早只能买在开盘。
- “封板”= 收盘价等于涨停价；“摸过涨停”= 最高价到过涨停价。
- 两组对照：同期全市场（不含 ST、科创板、北交所）；同一天里高开幅度不低于名单最低那只、开盘没涨停的其他股票。

**2026-01-07 到 2026-11-24，213 个交易日、2130 只的结果**

| | 竞价先锋 | 同样高开的其他股票 | 全市场 |
|---|---|---|---|
| 当天封住涨停 | 20.5% | 24.3% | 1.5% |
| 开盘买到收盘，赚钱的比例 | 41.2% | 45.9% | 47.3% |
| 开盘买到收盘，平均 | -0.63% | -0.79% | +0.02% |

- 85% 的交易日名单里至少有一只封板，平均每天 2 只。
- 第 1 名封板率 35.2%，第 4–10 名 16.2%；主板 28.3%，创业板 7.8%。
- 拿到第二天开盘平均 -0.62%。
- 也就是说：容易涨停是真的，但主要来自“高开”本身；开盘追进去平均是亏的。页面上原样展示了这些。

**已知的不准确之处**：历史名单是现在回头查的，“总市值、流通市值、是不是次新股”这几项问财可能用的是现在的数值，早期名单和当时实际看到的会有少量出入。页面底部写明了。

**接到别的功能上**

- 名单里每只票可以直接“拉群聊聊”。
- 群聊角色多了一个数据工具 `pick_list`（这只票在不在名单里、名单过去表现如何），炒股养家默认带；开群时如果这只票在名单里，开场信息里就会写上。
- 个股页上，在最近一次名单里的票会有一个小标记。

**菜单**

选股（今日名单 / 历史表现 / 方法库 / 我验证过的）· 问小四 · 行情 · 我的（账户 / 我的判断）。

## 5. 部署要点

- 服务器环境变量加 `SIXIANG_PICKS_AT=09:25:40`。不加的话页面照常能看历史，只是每天不会自动出新名单。
- 首次部署后在服务器上跑一次回填（约 200 次问财调用，几分钟）。
- 两张新表自动创建。
- 第一次打开历史表现要算几秒（之后按行情版本缓存）。
